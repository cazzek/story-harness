# シナリオの採用反映

`docs/シナリオ制作ハーネス.md` に従う。物語案の採用であり、Gitのcommit、push、外部サービスへの保存を許可する工程ではない。

## 前提

- 同じ作業領域の `レビュー.md` がPASSである
- ユーザーが、対象の正確な本文案と反映範囲を明示承認している。PASS、案の作成依頼、ハーネスの導入依頼だけを承認とみなさない。既存の承認が有効なら聞き直さない
- 文脈の全参照元と未作成状態、レビュー対象4ファイルのSHA-256が現在と一致する。不一致なら影響を確認して再レビューする。承認の内容も変わった場合だけ、新しい承認を求める
- ファイルと差分単位で反映対象が限定されている。正本や設定を変える候補には、その変更を含む明示承認がある

## 手順

1. 既存の差分を保護し、変更前のハッシュを記録する。承認された適用対応表の箇所だけを変更する。
2. 関連資料と場面索引を、必要な範囲で同期する。採用された抽出差分だけを `シナリオ管理/状態台帳.md` へ、時点、条件、本文根拠付きで追記する。
3. 識別子と接続、フラグ、戻り値を確認する。本文の形式に応じた検証（文法チェック、利用可能なlint、関連経路の確認など）を行う。未検証の項目を明記する。反映後の差分を見直し、対象外の保全を確認する。
4. `シナリオ管理/書式/反映記録.md` を使い、同名の作業ファイルを作る。承認範囲、レビューのSHA-256、前後ハッシュ、検証結果、一意な採用IDを記録する。
5. `シナリオ管理/採用履歴.jsonl` に、ハーネスに定める形式で1行追記する。過去行は変更、削除、並べ替えしない。全行のJSON妥当性とevent_idの一意性、追記前の内容の保持を確認する。
6. Git管理下なら差分の健全性確認を行い、管理なしならその事実と前後差分を記録する。結果、変更点、未検証点を短く報告する。反映の途中なら、完了扱いや成功イベントの追記をしない。

## 機械的修正

ハーネスの省略条件を満たす誤字修正は、工程ファイルなしでよい。対象箇所、正確な変更前後、検証、承認を会話から確認し、反映直前に元の内容を照合する。差分、承認、前後ハッシュを新しい作業領域の反映記録へ残す。採用履歴は同じ形式で追記し、全てのdeltasを空配列にする。物語の状態や知識は変更しない。
