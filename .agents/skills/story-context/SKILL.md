# シナリオの文脈

プロジェクトのルートを基準にパスを解決する。`AGENTS.md`、`docs/シナリオ制作ハーネス.md`、`シナリオ管理/正本と知識.md` に従う。設定への質問やハーネス保守では作業一式を作らない。

1. 依頼の目的と対象を確認し、`シナリオ管理/場面索引.md` から対象ファイルと識別子を解決する。新規の場面なら入口、出口、追加先を仮に定める。未指定の条件を決め打ちしない。
2. `シナリオ管理/作業/<対象>/<日付と目的>/` を作る。名前はプロジェクトの言語規則に合わせ、既存案を上書きしない。
3. 対象の前後の本文、該当する正本、必要な人物設定、関連する台帳の行だけを読む。全編や全人物の全文投入は不要。確認済みの参照は再利用する。
4. 読んだ全ソースのプロジェクト相対パス、役割、読んだ範囲、実測SHA-256、Git状態を記録する。Git管理がなければ「管理なし」。新規予定のファイルは「未作成」。既存の差分と資料の矛盾も記録する。
5. 時点と条件を固定し、作者意図、作中の事実、人物ごとに知る、信じる、疑う、知らない内容、読者への直接開示と推測を分ける。分からない値は未確定とする。
6. `シナリオ管理/書式/文脈.md` を使い、同名の作業ファイルへ保存する。本文、正本、台帳、採用履歴は変更しない。

他の作品や過去作の資料を検索して、この作品の正本を補完しない。正本を読んで知ったことを、人物や読者が知っているとは扱わない。次は `story-plan`。
