# シナリオの構成

`docs/シナリオ制作ハーネス.md` に従い、同じ作業領域の `文脈.md` を読む。参照元の現在のSHA-256と未作成状態を照合し、不一致なら文脈を更新してから進める。

1. 狙い、対象外、入口と出口、登場人物、不変条件を決める。通常は本命1案。複数案の依頼は尊重し、比較案の数と作中の選択肢の数を混同しない。
2. 感情、情報、選択、代償の流れを作る。書式の「場面で起こす変化」で、人物の望みと妨げ、行動、入口から出口への変化、本文で確かめる根拠を具体化する。説明だけの台詞や、同じ解決の繰り返しを点検する。選択肢がある場合は、異なる動機と固有の反応を置き、条件、合流、出口を示す。
3. 新しい分岐や大きな構造変更の前に、既存の構造の中で違いを作れないか検討する。
4. 変更ファイルと対象の範囲を限定する。作中の事実、人物の知識、読者の知識、関係、伏線の差分候補を分ける。
5. 増える場面、素材、フラグなど、制作量への影響を示す。全体への拡張は今回の目的に必要な分だけにする。
6. 新しい設定は未採用候補へ分離する。必須の判断を記録しつつ、依存しない執筆と検証を進める。
7. `シナリオ管理/書式/構成案.md` を使い、同名の作業ファイルへ保存する。`user_approved: false` のままにする。

本文、正本、台帳、採用履歴は変更しない。次は `story-write`。
