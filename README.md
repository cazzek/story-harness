# StoryHarness

AIエージェントと一緒に長編シナリオ（小説、ゲームのシナリオ等）を書くための制作ハーネスです。

長編を書き続けると、設定の矛盾、登場人物の知識の食い違い、「いつの間にか決まっていたことになる未決事項」に悩まされます。StoryHarnessは、執筆を決まった工程に分け、正本（確定した設定と本文）と制作中の案を厳密に分離することで、AIエージェントと人間が同じ前提で作業できるようにする仕組みです。

## 特徴

- **正本と案の分離**: 執筆中の案は作業フォルダにだけ作り、レビュー合格と作者の明示承認があるまで本文と正本を変更しません
- **6工程のスキル**: 文脈、構成、執筆、状態抽出、レビュー、採用反映の6工程を `.agents/skills/` に収録
- **情報の4層分離**: 作者意図、作中の事実、人物の知識と自覚、読者への開示を分けて扱い、知識の漏洩や先回りを防ぎます
- **参照のハッシュ照合**: 文脈に読んだ資料のSHA-256を記録し、工程ごとに照合します。途中で資料が変わったら先行工程に戻ります
- **根拠付きの状態管理**: 本文から抽出した状態変化は、本文の箇所を根拠として記録します。新しい設定は「未採用候補」に隔離し、確定扱いにしません
- **二値のレビュー判定**: 判定はPASSかBLOCKEDのみ。条件付き合格はなく、未決の判断が残れば進めません

## 構成

```text
AGENTS.md                     導入先プロジェクトの運用ルール（入口）
docs/
  シナリオ制作ハーネス.md      本体マニュアル
  AIへの指示例.md             AIエージェントへの頼み方のコピペ用プロンプト集
  文体ガイド_ひな形.md         文体と表記のルールを書くためのひな形
シナリオ管理/
  正本と知識.md               確定事項を集約するファイル（ひな形）
  状態台帳.md                 物語の状態変化の記録（ひな形）
  場面索引.md                 章と場面の一覧（ひな形）
  改稿の履歴.md               外部からの改稿を受けたときの記録（ひな形）
  採用履歴.jsonl              採用イベントの記録（空ファイル。形式はマニュアル参照）
  書式/                       各工程の成果物の書式（文脈、構成案、本文案、状態抽出、レビュー、反映記録）
  作業/                       制作中の案を置く場所
.agents/skills/
  story-context/              文脈づくり
  story-plan/                 構成
  story-write/                執筆
  story-extract/              状態抽出
  story-review/               レビュー
  story-commit/               採用反映
scripts/
  読点チェック.py             日本語本文の読点の偏りを数える簡易チェック
examples/
  使い方の例.md               ダミーの題材で工程の流れを追う短い例
```

## 使い方

1. このリポジトリの `AGENTS.md`、`docs/`、`シナリオ管理/`、`.agents/skills/`、`scripts/` を、自分の作品プロジェクトにコピーします
2. `シナリオ管理/正本と知識.md` に、自分の作品の確定事項（作品の前提、人物、文体、時系列）を記入します
3. `docs/文体ガイド_ひな形.md` を自分の作品の文体ガイドに育てます
4. AIエージェントに「第1章を書きたい」のように依頼します。エージェントは `AGENTS.md` を入口に、工程順に作業フォルダへ案を作ります
5. レビューがPASSになった案を確認し、採用する案だけを明示して承認します。承認された案だけが本文と正本へ反映されます

工程名を直接指定することもできます（例: `$story-context` で文脈だけ作る）。

## AIへの指示の出し方

入口は `AGENTS.md` です。AIエージェントには、まずこれと本体マニュアルを読ませてください。コピーして使える指示例を `docs/AIへの指示例.md` にまとめました。はじめの一言はこの形で十分です。

```text
このプロジェクトに StoryHarness を導入します。
まず AGENTS.md と docs/シナリオ制作ハーネス.md を読んで、工程の進め方と、
「案はレビュー合格と私の明示承認があるまで本編に反映しない」という原則を
理解したことを、短く要約して報告してください。
まだファイルは変更しないでください。
```

**心配な人は、導入前にAI自身に調査させてください。** 他人の作った仕組みを使うのが不安な場合は、使うAIエージェントにこのリポジトリ全体を精査させ、外部への送信、課金APIの呼び出し、認証情報や個人情報の収集、自動実行される処理がないかを、根拠となるファイル名とともに報告させることができます。そのための指示例も `docs/AIへの指示例.md` の「2. 心配な人向け」に用意しました。なお、同梱のスクリプトは `scripts/読点チェック.py` のみで、渡したテキストファイルの読点を数えるだけの処理です。

## 対象

- 章立て小説、連載小説、ビジュアルノベルやADV等のシナリオ全般
- 分岐のある作品では、文脈と状態抽出に「経路条件」の欄を足して使えます（マニュアルの「分岐を足す場合の拡張」参照）
- 対応するAIエージェントは、`AGENTS.md` と `.agents/skills/` の規約に従えるもの全般です

## カスタマイズの要点

- 正本と知識、文体ガイドの中身は作品ごとに違います。同梱のものはひな形と汎用原則だけです
- 工程の順番と「案は承認まで本編に触れない」という原則は、変えずに使うことをおすすめします
- 誤字修正だけのような軽い作業では工程を省略できます（条件はマニュアル参照）
