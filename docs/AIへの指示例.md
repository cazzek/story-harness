# AIへの指示例

StoryHarnessは、AIエージェントに `AGENTS.md` を読ませることが入口です。以下はコピーしてそのまま使える指示例です。角括弧の部分は自分の環境に合わせて書き換えてください。

## 1. まず読ませる（導入の最初に）

```text
このプロジェクトに StoryHarness を導入します。
まず AGENTS.md と docs/シナリオ制作ハーネス.md を読んで、工程の進め方と、
「案はレビュー合格と私の明示承認があるまで本編に反映しない」という原則を
理解したことを、短く要約して報告してください。
まだファイルは変更しないでください。
```

## 2. 心配な人向け（導入前にAI自身に調査させる）

他人の作った仕組みを使うのが不安な場合は、導入前に、使うAI自身にリポジトリ全体を調査させるのがおすすめです。

```text
このリポジトリを導入する前に、全体を調査してください。
次の観点で、根拠となるファイル名と行を挙げて報告してください。
- 外部へのネットワーク送信や、課金APIの呼び出しをする処理はないか
- 認証情報や個人情報を集める、または外部に送る処理はないか
- 自動で実行されるスクリプトや、ファイルの削除・上書きを行う処理はないか
- 含まれるスクリプトが、具体的に何を入力し、何を出力するか
問題が見つからなければ、その旨と、確認した範囲を報告してください。
この調査が終わるまで、導入や実行はしないでください。
```

参考として、同梱のスクリプトは `scripts/読点チェック.py` のみです。これは引数に渡したテキストファイルを読み、読点の数を数えて表示するだけの処理で、通信や書き込みは行いません。心配な場合は、AIにこのファイルから精査させてください。

## 3. 自分のプロジェクトへ導入してもらう

```text
私の作品プロジェクト [フォルダの場所] に StoryHarness を導入してください。
シナリオ管理/正本と知識.md には記入が必要な項目があります。
不明な項目は決め打ちせず、一つずつ私に質問して埋めてください。
```

## 4. 執筆を依頼する（通常の頼み方）

```text
AGENTS.md の工程に従って、[第N章／対象の場面] を進めてください。
文脈、構成、本文案、状態抽出、レビューまで作って提示してください。
採用反映（story-commit）はまだ行わないでください。
私が本文案を確認して承認したら、そのときに指示します。
```

## 5. 工程を一つだけ指定する

```text
$story-context だけを実行して、[対象] の文脈.md を作ってください。
```

工程名は `story-context`、`story-plan`、`story-write`、`story-extract`、`story-review`、`story-commit` の6つです。

## 6. レビューだけを依頼する

```text
[対象の作業フォルダ] の文脈、構成案、本文案、状態抽出を読み、
AGENTS.md と docs/シナリオ制作ハーネス.md の基準でレビューしてください。
判定は PASS か BLOCKED で、根拠を具体的に挙げてください。
本編は変更しないでください。
```
